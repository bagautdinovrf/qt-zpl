# Бенчмарки QtZpl

Измерения работают локально с версионированным корпусом. Labelary и сеть не
используются. Сборка бенчмарков включается отдельно и не добавляет временных
порогов в CTest.

## Запуск

```text
py -3 tools/build_helper.py benchmark
py -3 tools/build_helper.py benchmark --benchmark-filter parse/
py -3 tools/build_helper.py benchmark --benchmark-filter algorithm/qr/
py -3 tools/build_helper.py benchmark --benchmark-filter designer/
py -3 tools/build_helper.py benchmark --benchmark-samples 15 --benchmark-min-ms 100 --benchmark-output build_agent/build_agent_release/after.json
py -3 tools/compare_benchmarks.py build_agent/build_agent_release/before.json build_agent/build_agent_release/after.json
```

`benchmark` по умолчанию выбирает Release и записывает JSON в
`build_agent/build_agent_release/benchmark-results.json`. Сохраните исходный JSON под
другим именем до следующего запуска. `--config Debug` предназначен для
проверки стенда, а не для выводов о производительности. Для статической
библиотеки используйте `--static --build-dir build_agent/build_agent_release_static`.

Для обычного CMake: `-DQTZPL_BUILD_BENCHMARKS=ON`, затем цель
`qtzpl_benchmarks`. Это не требует Qt Test при `QTZPL_BUILD_TESTS=OFF`.
Сам EXE принимает `--help`, `--list`, `--filter`, `--corpus`, `--samples`,
`--min-ms`, `--warmup-ms`, `--output`. На Windows helper настраивает пути Qt
и DLL; при прямом запуске EXE их надо добавить в PATH. По умолчанию стенд
использует каталог корпуса и Font 0 из дерева исходников, поэтому standalone
EXE без исходников не является переносимым дистрибутивом.

## Что измеряется

- `parse/corpus/*`: только `parse(QStringView)` для 14 файлов; чтение файла
  и преобразование UTF-8 в QString происходят до таймера.
- `render/corpus/*`: `render(Document)` с уже разобранным документом,
  размерами и DPI из manifest. Время включает выделение и заполнение QImage,
  шрифты, кодирование штрихкодов и композицию.
- `end-to-end/corpus/*`: разбор плюс рендер того же файла. Файл может содержать
  две этикетки: `us/op` относится ко всему документу, `units_per_second` —
  к числу этикеток.
- `*/synthetic/*`: размеры пустого растра, повторяющийся/различный текст,
  длинные текстовые блоки, плотность GF, QR, MaxiCode, поля с запятыми и FH.
- `algorithm/*`: отдельно кодовые слова, ECC и полные модули штрихкодов;
  построение изображения в эти замеры не входит.
- `*/extensions/*`: девять добавленных типов штрихкодов, Code 128 U/Mod 10,
  прямоугольный DataMatrix, MaxiCode 3–6 и усечённый PDF417. Для каждого
  предусмотрены отдельные алгоритм, разбор, рендер и полный конвейер; `^FP`
  и совмещённые `^FO`/`^FT` + `^LT`/`^PM`/`^LR` проверяются на уровне конвейера.
  Подготовка этих кейсов отвергает любую диагностику, пустой растр и неверные
  размеры, сохраняет SHA-256 полных модулей/пикселей вне измеряемого участка.
- `component/*`: извлечённые пробы загрузки шрифта, построения контуров,
  выделения/заполнения изображения и накладных расходов стенда. Они объясняют
  затраты, но сами по себе не доказывают ускорение публичного API.
- `designer/*`: один неизменяемый разобранный документ из восьми этикеток:
  полный render, выбранная страница без/с геометрией, полный и постраничный
  analysis. Подготовка сверяет выбранный растр с полным render и число полей;
  fingerprints сохраняют пиксели выбранной страницы, фактическое число
  выходных изображений и метаданные соответствующей операции. Отдельные пары
  сравнивают декодирование compressed/Z64-графики в packed bytes с рендером
  той же графики на холсте 812×406. Полное хеширование выполняется до таймера;
  анализ и геометрия имеют собственные fingerprints, не заменяющие тесты.

## Методика и проверка результатов

Стенд однопоточный, измеряет wall time через `steady_clock`. После подготовки
и валидации входов каждый кейс прогревается; число повторений подбирается под
целевую длительность пакета. По умолчанию: 20 мс прогрева, целевые 50 мс
на пакет, девять пакетов. Итог — медиана среднего времени операции в пакете.
JSON сохраняет все пакеты, min/max, MAD и p95 **средних по пакетам**;
это не p95 задержки отдельных запросов. Уничтожение результата входит во
время операции, файловый ввод-вывод и полное хеширование изображений — нет.

Шрифтовые и ECC-кэши прогреты. Первая загрузка библиотеки, запуск приложения
и холодная инициализация статических таблиц не измеряются. Кэш внутри одного
`render()` создаётся заново при каждом вызове и входит в измеренное время.
Тесты отдельно проверяют конкурентную первую инициализацию ECC-кэшей.

Для 69 parser/render/end-to-end кейсов сохраняется SHA-256 результатов:
полные пиксели, размеры и формат изображения, диагностики; для парсера —
структура команд, исходный текст, смещения и декодированные FD/GF/штрихкоды.
Числовые поля всех вариантов модели не сериализуются целиком: этот fingerprint
не заменяет parser-тесты. Алгоритмы защищены векторными и дифференциальными
тестами полных кодовых слов/матриц. Короткий checksum внутри таймера только
предотвращает удаление вычислений компилятором.

`compare_benchmarks.py` проверяет совместимость среды и нагрузки, сообщает
изменённые fingerprints и завершается с ошибкой при расхождении. Пустые
fingerprints алгоритмов не считаются подтверждением равенства модулей.
Новые/пропавшие кейсы перечисляются отдельно и не участвуют в сравнении.

Запускайте до/после на одной машине, с одним Qt backend и типом сборки,
последовательно, без одновременно работающей сборки. Для малых изменений
повторите серии в чередующемся порядке. Сравнивайте выигрыш с разбросом и
контрольными кейсами. Нельзя складывать времена независимо измеренных этапов
или обещать одинаковое ускорение для любых этикеток.

Серия новых команд и проверки глифов: [COMMAND-EXTENSIONS-2026-10-07.md](COMMAND-EXTENSIONS-2026-10-07.md).

Дополнительные сведения о машине и версии можно записать в JSON через
`QTZPL_BENCH_CPU` и `QTZPL_BENCH_REVISION`. Остальные параметры среды стенд
определяет автоматически. Результаты текущего исследования: [RESULTS.md](RESULTS.md).
